# Автоматизация тестирования веб-приложения

Учебный проект по автоматизации тестирования веб-приложения. Цель проекта — освоить построение поддерживаемого автотестового фреймворка на Python: от API-клиентов и моделей данных до фикстур, проверок и тестовых сценариев.

## Текущий статус

Проект находится в работе. На текущем этапе заложена основа для API-автоматизации и реализованы компоненты, необходимые для проверки авторизации.

## Проверяемые сущности

В проекте выделены маршруты веб-приложения для следующих сущностей:

- авторизация: регистрация и вход пользователя;
- пользователи;
- комнаты;
- бронирования;
- проверка доступности сервиса (`health`).

Сейчас основное внимание уделено сценариям регистрации и входа. Для них подготовлены API-клиент, Pydantic-схемы запросов и ответов, фикстура клиента, генератор тестовых данных и переиспользуемые проверки ответов.

## Структура проекта

```text
.
├── src/api/
│   ├── assertions/  # Переиспользуемые проверки API-ответов
│   ├── clients/     # Базовый и специализированные HTTP-клиенты
│   ├── fixtures/    # Pytest-фикстуры
│   ├── schemas/     # Pydantic-модели запросов и ответов
│   └── tools/       # Маршруты и генерация тестовых данных
├── tests/api/       # API-автотесты
├── conftest.py      # Общие настройки pytest
├── pytest.ini       # Конфигурация pytest
└── requirements.txt # Зависимости проекта
```

- Python 3.14 (проверенная версия);

- Pydantic;

## Первый запуск

Проект проверялся на Windows с Python 3.14. Для изолированной установки:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

`pydantic-settings` нужен для загрузки настроек из `config.py`. `tzdata`
поставляется явно: на Windows он предоставляет IANA-данные для
`ZoneInfo("Europe/Moscow")`, используемого генератором тестовых данных.

Создайте локальный `.env` на основе `.env.example` и укажите адрес доступного
BookingLab API в `CLIENT_SETTINGS.BASE_URL`. В репозитории нет самого
тестируемого приложения и готовых учётных записей: их источник, запуск и
данные определяет владелец API.

Проверки стиля используют системные команды `ruff` и `pre-commit`, поэтому
установите их в активное окружение и зарегистрируйте hooks:

```powershell
python -m pip install ruff pre-commit
pre-commit install
ruff check --no-cache --select E4,E7,E9,F,I .
ruff format --no-cache --check .
```

После настройки окружения коллекцию тестов можно проверить командой:

```powershell
pytest --collect-only -q
```

На текущем этапе модули в `tests/api` подготовлены, но сценарии в них ещё не
реализованы; поэтому пустая коллекция не является успешным прогоном тестов.
